# SoundPad

Общий саундпад для компании друзей в Discord. Один человек держит сервер, у всех остальных стоит программа для Windows. Звуки, которые загрузил кто угодно, сразу появляются у всех.

- **Сервер** (`server/`) — Node.js + SQLite. Хранит аккаунты и звуки, рассылает изменения по WebSocket. Запускается в Docker.
- **Клиент** (`client/`) — Electron, тёмная тема в стиле Discord. Кэширует звуки локально, играет их в наушники и в виртуальный кабель для Discord, подмешивает туда микрофон.

## Возможности

- Аккаунты: ник + пароль. Регистрация только по одноразовому инвайт-коду от админа. Первый зарегистрированный на новом сервере сам становится админом.
- Общая коллекция с категориями, поиском, избранным и разделом «Мои звуки».
- Загрузка: кнопкой, перетаскиванием файлов и папок в окно. Подпапки становятся категориями, одинаковые файлы не дублируются.
- Живая синхронизация: добавили, переименовали или удалили звук, и он сразу меняется у всех. Список «В сети», как в Discord.
- Аватарки (PNG, JPG, WEBP или анимированный GIF) и звания по числу загруженных звуков. Чем выше звание, тем ярче ник:

  | Звание | Звуков | Ник |
  |---|---|---|
  | Тихоня | 0 | серый |
  | Слушатель | 1+ | белый |
  | Звукач 🎧 | 5+ | зелёный с подсветкой |
  | Диджей 💿 | 15+ | градиент |
  | Звукорежиссёр 🎛️ | 30+ | переливающийся градиент |
  | Легенда 👑 | 60+ | золото с бликом |
  | Бог саундпада ⚡ | 100+ | радуга |

  Названия, пороги, иконки и стиль ника (10 вариантов, от «Серого» до «Голограммы») админ меняет в **Админка → Звания**. Там же, в **Пользователях**, можно вручную выдать звание конкретному человеку. При наведении на ник по нему пробегает блик.
- Админка → **Категории**: переименовать, объединить (переименовать в существующую) или убрать категорию.
- Перемотка: в нижней панели ползунок для звука, который играет сейчас.
- Глобальные горячие клавиши (работают в игре) и клавиша «Стоп всё» (по умолчанию `Ctrl+Alt+0`).
- Админка:
  - **Из папки на ПК**: выбрать папку, отметить файлы, поправить названия и категории, загрузить.
  - **С сервера**: импорт из папки `data/import` прямо на сервере, без передачи через интернет.
  - Пользователи (выдать или снять админку, сбросить пароль, удалить) и инвайты.
- Обычные участники могут загружать звуки, а менять и удалять только свои. Админ может всё. Загрузку только для админа можно включить настройкой `USERS_CAN_UPLOAD=false`.

## 1. Сервер (у друга на ПК через Docker)

1. Установить [Docker Desktop](https://www.docker.com/products/docker-desktop/) и запустить его.
2. Скачать этот репозиторий (зелёная кнопка **Code → Download ZIP**) и распаковать, например, в `C:\SoundPad`.
3. Открыть в этой папке терминал (правый клик → «Открыть в терминале») и выполнить:
   ```
   docker compose up -d --build
   ```
4. Проверить, что сервер работает: открыть в браузере http://localhost:8787/api/info, там должен быть ответ с `"name":"SoundPad"`.

Все данные лежат в папке `data` рядом с `docker-compose.yml`: база `soundpad.db`, звуки `sounds/` и папка для импорта `import/`. **Бэкап — это просто копия папки `data`.**

Полезные команды:

| Что | Команда |
|---|---|
| Остановить | `docker compose down` |
| Обновить после `git pull` | `docker compose up -d --build` |
| Посмотреть логи | `docker compose logs -f` |

### Как друзьям достучаться до сервера

ПК с сервером должен быть включён, а порт **8787** доступен остальным. Варианты:

- **Radmin VPN или ZeroTier** (проще всего, роутер трогать не надо). Все ставят программу и входят в одну сеть. Адрес сервера — IP ПК друга в этой сети, например `26.123.45.67:8787`.
- **Проброс порта на роутере.** Нужен белый IP от провайдера. На роутере пробросить TCP 8787 на ПК с сервером, в брандмауэре Windows разрешить порт 8787. Адрес сервера — внешний IP.

### Переезд на VPS потом

Поставить на VPS Docker, скопировать туда репозиторий и папку `data`, выполнить `docker compose up -d --build`. В клиентах поменять адрес сервера: выйти из аккаунта и войти с новым адресом. Все звуки и аккаунты сохранятся.

Если сервер смотрит прямо в интернет, лучше поставить перед ним HTTPS, например Caddy с доменом. Иначе пароли идут открытым текстом. Клиент понимает адреса `https://…`.

### Без Docker (быстрый запуск на своём ПК)

Установить [Node.js](https://nodejs.org) 22 или новее и дважды щёлкнуть `server\start-server.bat`. При первом запуске он сам поставит зависимости. В окне появятся адреса для программы: на этом же ПК — `localhost:8787`. Данные хранятся в `server\data`.

## 2. Клиент для Windows

**Скачать:** раздел [Releases](https://github.com/ProstoShrek/FriendSP/releases/latest) → `SoundPad-Setup-*.exe`. Есть и `SoundPad-Portable-*.exe`, он работает без установки, но сам не обновляется.

**Автообновление.** Установленная программа сама проверяет релизы при запуске и раз в 2 часа, скачивает новую версию в фоне и ставит её при следующем запуске. Можно не ждать: нажать зелёную кнопку «Обновить до …» в заголовке окна.

**Как выпустить новую версию:**
1. Поменять `"version"` в `client/package.json`, например на `0.3.0`, и смержить в `main`.
2. Создать релиз с тегом `v0.3.0`: на GitHub **Releases → Draft a new release → Choose a tag → v0.3.0 → Create new tag** → **Publish release**. Или из консоли: `git tag v0.3.0 && git push origin v0.3.0`.
3. Через 5–7 минут GitHub Actions соберёт установщик и выложит его в релиз. Программы у друзей подтянут обновление сами.

Версия в теге должна совпадать с версией в `package.json`, иначе сборка остановится с ошибкой.

> Windows SmartScreen может предупредить о «неизвестном издателе», потому что у программы нет платной подписи. Жмите «Подробнее → Выполнить в любом случае».

Собрать самому: установить Node.js 22, затем `cd client`, `npm install`, `npm run dist`. Готовые файлы появятся в `client/dist`. Для запуска без сборки: `npm start`.

### Первый вход

1. Адрес сервера, например `26.123.45.67:8787`. Порт 8787 подставится сам, если указан только IP.
2. **Админ** (первый человек на новом сервере) просто регистрируется, инвайт не нужен.
3. Остальным админ делает инвайт: **щит в верхней панели → Инвайты → Создать инвайт**. В буфер копируется готовое сообщение с адресом и кодом, его можно сразу кинуть в Discord.

## 3. Чтобы друзья в Discord слышали звуки

Discord берёт звук только с микрофона, поэтому нужен виртуальный кабель.

1. Установить бесплатный **VB-Cable**: https://vb-audio.com/Cable/ (запустить `VBCABLE_Setup_x64.exe` от администратора) и перезагрузить ПК.
2. В SoundPad: **шестерёнка → Звук и Discord**:
   - «Вывод в Discord» → **CABLE Input** (обычно выбирается сам);
   - «Подмешивать микрофон» → включено, выбрать свой микрофон.
3. В Discord: **Настройки → Голос и видео → Устройство ввода → CABLE Output (VB-Audio Virtual Cable)**.

Теперь друзья слышат и тебя, и звуки. Громкость «Мне» и «В Discord» регулируется отдельно в нижней панели. Иконка микрофона внизу слева включает и выключает подмешивание голоса.

Если используешь режим рации (push-to-talk) в Discord, звуки тоже будут слышны только пока зажата клавиша. Удобнее режим активации по голосу.

## Настройки сервера

Задаются в `docker-compose.yml` в разделе `environment`:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MAX_FILE_MB` | `15` | Максимальный размер одного звука |
| `USERS_CAN_UPLOAD` | `true` | `false` — загружать может только админ |
| `PORT` | `8787` | Порт внутри контейнера |
| `IMPORT_DIR` | `/data/import` | Папка для импорта «с сервера» |

## Разработка

```
cd server && npm install && npm start    # сервер на :8787, данные в server/data
cd server && npm test                    # тесты API
cd client && npm install && npm start    # клиент
```

Структура клиента: `src/main.js` — окно, кэш звуков, загрузка файлов, глобальные клавиши; `src/preload.js` — мост к окну; `src/renderer/` — интерфейс (`app.js` — экраны, `audio.js` — аудиодвижок, `admin.js`, `upload.js`, `ui.js`, `styles.css`).
